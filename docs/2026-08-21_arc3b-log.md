- [AGENT] Value-domain decision: Alir mirrors al/ast.ml's `value` type
  faithfully (ListV as List not growable array — documented; no
  mutation in Lean) and the interpreter USES it; the agreement harness
  converts IL value exps → Alir values at its boundary (conversion is
  harness code, fail-closed). Global mutable state (WasmContext value
  stack, Store) becomes explicitly threaded state — documented
  representation divergence (identical semantics, no globals in Lean).

- [AGENT] Harness design decisions: (1) the rule-direct side runs the
  FULL `Step` relation on a minimal config (empty store, dummy frame —
  list-shaped placeholders in non-list fields; pure rules never inspect
  them, and any rule that did would surface as visible stuck, never a
  false agree) and reuses Runner.runConfig verbatim — first attempt
  used Step_pure directly and could not decompose sequences (sequence
  splitting lives in Step/ctxt-instrs); (2) ofIlValue projects
  anonymous SINGLETON wrapper cases to their payload, matching
  construct.ml's bare-literal AL values (driver output
  `(C "CONST" (C "I32") (N 1))`); multi-arg anonymous cases keep
  CaseV "" (construct.ml:1202); (3) first full run: 24/24 AGREE,
  wall 10m08s — dominated by the rule-direct engine (arc-3a's
  problem); the Alir side alone runs all cases in 0.3 s.
